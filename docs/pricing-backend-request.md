# 요금제 개편 백엔드 반영 요청서

**FEDIT · 요금제 개편** · 2026-09-27 · 프론트 → 백엔드 요청

설정 화면의 요금제 카드(Basic·Pro·Enterprise) 내용을 새 가격·기능 구성으로 바꿨습니다. 화면은 이미 나갔지만 서버 쪽 결제 금액·플랜별 사용량 제한은 아직 이전 상태라, 실제로 맞춰야 할 항목을 정리했습니다.

## 요약

| # | 요청 | 난이도 | 비고 |
| --- | --- | --- | --- |
| 1 | Basic 첫 달 프로모션 (29,000원 → 59,000원) | **핵심 · 높음** | "몇 번째 결제인지" 서버가 판단해야 금액 분기 가능 |
| 2 | Pro 플랜 실제 결제 전환 (문의 전용 → 99,000원 정기결제) | 중간 | plan_code(`pro`)는 이미 있음, 청구 활성화 여부 확인 |
| 3 | 플랜별 사용량 제한 변경 (브랜드 모니터링·엑셀 다운로드 등) | 중간 | Pro가 무제한 → 제한으로 축소, 일부 기능은 Enterprise 전용화 |

## 1. 가격 변경

아래는 화면에 나가 있는 최종 숫자입니다. 서버의 플랜별 청구 금액을 이 값으로 맞춰주세요.

| plan_code | 정가 | 판매가 | 비고 |
| --- | --- | --- | --- |
| `basic` | ~~72,000원~~ | 59,000원 (2회차부터) | 첫 결제는 29,000원 (18%↓ 기준가에서 첫 달만 별도 프로모션 — 2번 참고) |
| `pro` | ~~165,000원~~ | 99,000원 | 프로모션 없이 매달 동일 금액. **기존 "문의하기" → 실제 정기결제로 전환** |
| `basic_secret` | — | 19,000원 | 비밀 링크 유입 전용. 이것도 "첫 달만"인지 계속인지 2번에서 같이 확인 필요 |
| `enterprise` | 문의 전용 (결제 대상 아님) | | 변경 없음 |

> **basic_secret은 새로 만든 코드가 아닙니다.** 기존에 있던 plan_code(비밀 링크 특가)를 그대로 씁니다. 새 plan_code 추가 없이, 이미 있는 세 코드(`basic` · `pro` · `basic_secret`)의 금액만 맞추면 됩니다.

## 2. Basic 첫 달 프로모션 — 결제 주기 판단이 필요합니다

이번 요청에서 유일하게 프론트만으로는 해결이 안 되는 항목입니다. 먼저 상황을 정리하고, 아래에 필요한 걸 여쭤봅니다.

### 왜 프론트가 판단할 수 없나요

정기결제는 Toss 빌링키로 등록된 뒤 서버 스케줄러가 매달 자동으로 청구합니다. 프론트는 최초 결제 화면 한 번만 관여하고, 2회차 이후 청구에는 관여하지 않습니다. 즉 "이번이 몇 번째 결제인지"는 서버만 알 수 있는 정보이고, 청구 금액을 그 값에 따라 다르게 넣는 로직도 서버(또는 Toss 쪽 정기결제 설정)에 있어야 합니다.

### 여쭤보고 싶은 것

1. **구독 레코드에 결제 회차(또는 가입일) 정보가 이미 있나요?** 있다면 "1회차만 29,000원, 2회차부터 59,000원"으로 청구 금액을 분기할 수 있는지 확인 부탁드립니다.
2. **basic_secret(19,000원)은 지금 첫 달만 19,000원이고 그 이후 자동으로 정가로 바뀌나요, 아니면 계속 19,000원으로 청구되나요?** 만약 "첫 달만 특가 → 이후 자동 전환" 구조가 이미 구현돼 있다면, 그 메커니즘을 basic의 첫 달 프로모션(29,000원 → 59,000원)에도 그대로 재사용할 수 있을 것 같습니다.
3. **안 되어 있다면**, basic_secret과 같은 패턴으로 `basic_first` 같은 임시 plan_code를 하나 더 만들어 1회 결제 후 자동으로 `basic`으로 전환시키는 방식을 제안드립니다. 이 경우 프론트는 최초 결제 시 `basic_first`로 요청만 보내면 되고, 이후 전환은 서버가 처리합니다.
4. **해지 후 재구독 시** 다시 "첫 결제"로 쳐서 29,000원을 또 적용할지, 평생 1회만 적용할지 정책을 정해주세요. (참고: 지금 화면 문구는 "첫 달"이라고만 돼 있어 프론트 쪽에서 별도로 막고 있는 조건은 없습니다.)

> **참고 — 지금 화면에 나가 있는 문구.** Basic 카드: "18% 할인 · 첫 달 29,000원" + 큰 글씨로 "59,000원/월". 결제 확인 모달에는 별도 첫 달 안내 문구가 아직 없어서, 서버 쪽 처리 방식이 정해지면 필요 시 모달 문구도 추가하겠습니다.

## 3. Pro 플랜 실제 결제 전환

Pro는 지금까지 "문의하기"만 있고 자체 결제 로직이 없었습니다. 화면은 Basic과 동일한 결제 확인 모달 → Toss 정기결제 흐름으로 이미 연결해뒀습니다.

- 프론트 변경: 요금제 카드에서 Pro를 클릭하면 Basic과 같은 방식으로 결제 확인 모달이 뜨고, 동의 후 `PostChangePlan("pro")` 또는 Toss `requestBillingAuth`(신규 결제 시)를 호출합니다. 코드 상으로는 이미 `PlanType`에 `"pro"`가 있어서 타입 레벨에서는 준비돼 있었습니다.
- 확인 요청: `PostChangePlan("pro")` 및 결제 승인 콜백(`PostConfirmBilling` 등)에서 pro plan_code로 결제 시 **실제로 99,000원이 청구되도록 금액이 설정돼 있는지** 확인 부탁드립니다. 지금까지 pro가 "문의 전용"이었다면 서버에 청구 로직 자체가 없을 수도 있어서요.
- 기존에 이미 Pro로 계약 중인 고객이 있다면, 이번 개편으로 가격(99,000원)이나 사용량 제한(4번)이 바뀌는 게 기존 고객에게도 소급 적용되는지 정책을 확인해주세요.

## 4. 플랜별 사용량 제한 변경

다운로드 횟수, 모니터링 브랜드 수처럼 서버가 실제로 막아줘야 하는 항목들입니다. Basic은 숫자가 그대로지만, Pro는 "무제한"이던 게 이번에 캡이 생기고 일부 기능은 Enterprise 전용으로 빠졌습니다.

| 항목 | Basic | Pro | Enterprise |
| --- | --- | --- | --- |
| 모니터링 브랜드 수 | 5개 _(변경 없음)_ | **30개 (신규 — 기존 무제한)** | 무제한 |
| 엑셀 다운로드 | 월 3회 _(변경 없음)_ | **월 30회 (신규 — 기존 무제한)** | 무제한 |
| 유형·색상·소재 분석 | 미제공 | 제공 _(변경 없음)_ | 제공 |
| 패션쇼 분석 | 미제공 | 제공 _(변경 없음)_ | 제공 |
| 월간 트렌드 리포트 | 미제공 | **미제공 (신규 — 기존 제공)** | 제공 |
| AI Agent | 미제공 | **미제공 (신규 — 기존 제공)** | 제공 |
| 신규 브랜드 분석 신청 | 화면 문구에서 제거 | 화면 문구에서 제거 | 화면 문구에서 제거 |

> ⚠️ **Pro는 늘어난 게 아니라 줄었습니다.** 브랜드 모니터링·엑셀 다운로드가 무제한 → 숫자 제한으로 바뀌고, 월간 트렌드 리포트·AI Agent는 Enterprise로 넘어갔습니다. 기존 Pro 이용자가 있다면 안내 없이 갑자기 막히는 일이 없도록, 서버 반영 시점과 고객 공지 시점을 맞춰주세요.

### API 관점에서 확인이 필요한 부분

- **브랜드 선택 방식** — Basic은 온보딩에서 정확히 5개를 강제로 고르게 하는 화면(관심 브랜드 모달)이 이미 있습니다. Pro의 30개도 "정확히 30개 강제 선택"인지 "최대 30개까지 자유 선택"인지에 따라 프론트 UI가 달라져서, 정책을 알려주시면 그에 맞춰 화면을 만들겠습니다.
- **엑셀 다운로드 한도 API** — 지금 Basic 월 3회 한도는 `GetExcelDownloadUsage` / `PostExcelDownload`로 이미 처리 중입니다. 같은 API가 플랜별로 다른 한도(Pro는 30회)를 이미 받을 수 있는 구조인지, 아니면 서버 쪽에 Pro용 한도값을 추가해야 하는지 확인 부탁드립니다.

## 5. 체크리스트

- [ ] Basic 정가·판매가 확정 (72,000원 / 59,000원)
- [ ] Pro 정가·판매가 확정 (165,000원 / 99,000원) 및 실제 청구 활성화
- [ ] Basic "몇 회차 결제인지" 판단 방식 확정 (2번)
- [ ] basic_secret 첫 달 이후 동작 방식 확인
- [ ] Pro 브랜드 모니터링 30개 제한 서버 enforcement
- [ ] Pro 엑셀 다운로드 월 30회 제한 서버 enforcement
- [ ] Pro의 월간 트렌드 리포트·AI Agent 제거 (기존 고객 소급 여부 포함)
- [ ] 신규 브랜드 분석 신청 기능 — 화면 문구에서는 뺐는데, 백엔드 기능 자체는 유지할지 확인
